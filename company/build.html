Making this shared

Right now this portal saves to whichever browser you opened it in. GitHub Pages serves files; it cannot hold state, so a shared board needs one small database behind it. Supabase's free tier is enough for a team of four, and the setup is five minutes. Until then the Export button gives you the whole board as a file.

  1. Make a free project at supabase.com.
  2. In the SQL editor, run the block below. It makes one table with one row. The three policies as written let anyone holding the key read and write it, so read the warning under the block before you use them as they are.
  3. Open Project Settings → API and copy the Project URL and the anon key.
  4. Paste both into the SYNC block at the top of company/build.js, commit, and push. The header will read Shared instead of This device only.
create table almari_workroom (
  id int primary key,
  doc jsonb not null,
  updated_at timestamptz default now()
);
alter table almari_workroom enable row level security;

-- Open to anyone with the key. Fine on a private host, NOT on a public URL:
create policy "team read"  on almari_workroom for select using (true);
create policy "team write" on almari_workroom for insert with check (true);
create policy "team edit"  on almari_workroom for update using (true);

-- Safe on a public URL. Turn on Supabase Auth, invite the team, then use these
-- instead of the three above:
-- create policy "team read"  on almari_workroom for select using (auth.uid() is not null);
-- create policy "team write" on almari_workroom for insert with check (auth.uid() is not null);
-- create policy "team edit"  on almari_workroom for update using (auth.uid() is not null);

The key cannot go in a public repository. This site is served from a public repo, so committing the anon key alongside the open policies above publishes read and write access to this board to everyone. For task titles that is untidy; the moment the board holds anything about a real person, a tester's email or a journalist's number, it is a personal-data breach and the company answers for it under the DPDP Act. Either serve the board from a private host, or turn on Supabase Auth and use the commented policies. Never put passwords, bank details, or anything about a person who has not consented into this board.
